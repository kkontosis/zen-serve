# zen-serve specification

This directory is **normative**. The design documents in `docs/` explain *why*; `spec/` says exactly *what*, down to the byte. If code and spec disagree, it's a bug, and the test suite is meant to catch it.

## Conventions

* All integers are **big-endian**. `u32(x)` means 4 bytes.
* `||` means concatenation.
* `lp(x) = u32(len(x)) || x`.
* Hex in the vectors is lowercase.
* Every stored object starts with `format_version` (currently `1`) and `suite`. Readers reject versions and suites they don't know (G4).

## Regenerating test vectors

```sh
cargo run -p zen-core --example gen_vectors --features test-utils
```

The vectors use a deterministic RNG (the BLAKE3 XOF of a seed string, label `zen/test/det-rng`). Each vector records its seed. That RNG exists only for vectors and tests. Production code uses the operating system RNG.
